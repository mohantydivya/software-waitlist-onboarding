## Problem statement

Early-stage software teams run waitlists from forms and spreadsheets, so three things go wrong. Founders can't see how many prospects drop out between signing up and using the product. Approvers have no consistent way to decide who gets access first. Approved prospects get ad-hoc emails with no guided path to first use.

**Workflow being improved:** approving prospects against a launch capacity, from queue to invite.

## Decision the product supports

Which prospect to admit next, and whether a prospect can be approved, put on hold, rejected, onboarded or marked activated.

## Hypothesis

A single status-transition function that validates every change and every role, combined with a visible funnel status and a capacity-based approval queue, will remove out-of-order or unauthorized approvals and reduce the effort of admitting prospects.

The first half can be checked with the automated tests. The "reduce the effort" half needs the peer walkthrough below.
